# MIDI Tuner

A small browser-based MIDI testing app. It uses Vite for local development and
WebMidi.js to access MIDI devices through the browser's Web MIDI API.

## Project structure

```text
midi-tuner/
├── src/
│   ├── main.js             # App entry point; connects MIDI, UI, and controls
│   ├── styles.css          # App layout and visual styles
│   ├── midi/
│   │   ├── active-notes.js # Tracks held notes and clears disconnected inputs
│   │   ├── midi-client.js  # Enables WebMidi.js and listens for note events
│   │   └── midi-utils.js   # Small MIDI utility functions
│   └── ui/
│       ├── device-list.js  # Renders detected MIDI input/output devices
│       ├── piano.js        # Builds the 88-key piano and highlights held notes
│       └── test-controls.js # Wires the MIDI enable button
├── tests/
│   └── midi-utils.test.js  # Unit tests for MIDI utility functions
├── index.html              # Page markup and app mount point
├── package.json            # Dependencies and npm commands
├── package-lock.json       # Exact dependency versions installed by npm
├── vite.config.js          # Vite configuration
├── start-localhost.ps1     # Windows helper to start the local dev server
└── INSTALLATION.md         # Runtime/dependency installation notes
```

`node_modules/` contains installed dependencies, and `dist/` is generated by a
production build. They are generated folders rather than application source.

## Launch from Visual Studio Code

1. Open the project folder in Visual Studio Code.
2. Open **Terminal → New Terminal**. The terminal should start in the project
   folder.
3. In PowerShell, start the local server:

   ```powershell
   .\start-localhost.ps1
   ```

4. Open the URL printed in the terminal, usually
   [http://127.0.0.1:5173/](http://127.0.0.1:5173/).
5. Keep the terminal open while using the app. Press **Ctrl+C** in that
   terminal to stop the server.

The helper uses the portable Node.js runtime documented in
[INSTALLATION.md](./INSTALLATION.md), installs project dependencies if Vite is
not present, and binds Vite to `127.0.0.1` so the development server is only
available from this computer. If PowerShell blocks running the script due to
execution policy, use the manual commands below instead.

### Manual start

If Node.js and npm are on your `PATH`, run:

```powershell
npm install
npm run start
```

If you are using the portable runtime installed by the setup notes, add it to
the current PowerShell session first:

```powershell
$nodeDir = Join-Path $env:LOCALAPPDATA 'Programs\nodejs-v26.13.1\node-v26.13.1-win-x64'
$env:PATH = "$nodeDir;$env:PATH"
npm install
npm run start
```

## MIDI access

Select **Enable MIDI** in the page and grant browser permission if prompted.
Connect a MIDI input and play or release notes to see the corresponding keys
light up or turn off on the 88-key A0–C8 piano. MIDI access requires a
supported browser and a secure context; `localhost` and `127.0.0.1` are
suitable for local development. Notes remain lit until their matching note-off
arrives; if an input disconnects while a note is held, its keys are cleared.
The current app displays incoming MIDI notes; it does not yet send MIDI output.

## Build process

The production build is created by Vite. From the project folder, run:

```powershell
npm install
npm run build
```

`npm install` installs the dependencies listed in `package.json` (with exact
resolved versions recorded in `package-lock.json`). The build command runs
`vite build`: it reads `index.html`, follows the JavaScript and CSS imports
from `src/`, bundles and optimizes the app, and writes the deployable static
files to `dist/`. Vite clears and recreates that output folder during a build;
do not make source edits directly in `dist/`.

To check the production build locally, run:

```powershell
npm run preview
```

Vite prints a local preview URL. This preview serves the built files; for
day-to-day development, use `npm run start` or `.\start-localhost.ps1` instead.
