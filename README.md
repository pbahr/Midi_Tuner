# MIDI Tuner

A small browser-based MIDI testing app. It uses Vite for local development and
WebMidi.js to access MIDI devices through the browser's Web MIDI API.

## Project structure

```text
midi-tuner/
├── src/
│   ├── main.js             # App entry point; connects MIDI, UI, and controls
│   ├── styles.css          # App layout and visual styles
│   ├── audio/
│   │   └── piano-sound.js  # Loads and plays sampled grand piano soundfont
│   ├── midi/
│   │   ├── active-notes.js # Tracks held notes and clears disconnected inputs
│   │   ├── midi-client.js  # Handles MIDI note, pedal, and device events
│   │   ├── midi-output.js  # Routes incoming notes and sustain to selected output
│   │   ├── midi-tuning.js  # Converts cents offsets to pitch-bend values
│   │   ├── midi-recorder.js # Records and encodes MIDI Standard MIDI Files
│   │   ├── midi-utils.js   # Small MIDI utility functions
│   │   ├── pitch-offsets.js # Cycles per-key tuning offsets
│   │   └── sustain-pedal.js # Tracks MIDI sustain pedal state
│   └── ui/
│       ├── device-list.js  # Renders detected MIDI input/output devices
│       ├── piano.js        # Builds the 88-key piano and highlights held notes
│       └── test-controls.js # Wires the MIDI enable button
├── tests/
│   └── midi-utils.test.js  # Unit tests for MIDI utility functions
├── index.html              # Page markup and app mount point
├── package.json            # Dependencies and npm commands
├── package-lock.json       # Exact dependency versions installed by npm
├── vite.config.js          # Vite configuration
├── start-localhost.ps1     # Windows helper to start the local dev server
└── INSTALLATION.md         # Runtime/dependency installation notes
```

`node_modules/` contains installed dependencies, and `dist/` is generated by a
production build. They are generated folders rather than application source.

## Launch from Visual Studio Code

1. Open the project folder in Visual Studio Code.
2. Open **Terminal → New Terminal**. The terminal should start in the project
   folder.
3. In PowerShell, start the local server:

   ```powershell
   .\start-localhost.ps1
   ```

4. Open the URL printed in the terminal, usually
   [http://127.0.0.1:5173/](http://127.0.0.1:5173/).
5. Keep the terminal open while using the app. Press **Ctrl+C** in that
   terminal to stop the server.

The helper uses the portable Node.js runtime documented in
[INSTALLATION.md](./INSTALLATION.md), installs project dependencies if Vite is
not present, and binds Vite to `127.0.0.1` so the development server is only
available from this computer. If PowerShell blocks running the script due to
execution policy, use the manual commands below instead.

### Manual start

If Node.js and npm are on your `PATH`, run:

```powershell
npm install
npm run start
```

If you are using the portable runtime installed by the setup notes, add it to
the current PowerShell session first:

```powershell
$nodeDir = Join-Path $env:LOCALAPPDATA 'Programs\nodejs-v26.13.1\node-v26.13.1-win-x64'
$env:PATH = "$nodeDir;$env:PATH"
npm install
npm run start
```

## MIDI access

Select **Enable MIDI & Piano Audio** in the page and grant browser permission
if prompted. The app loads an acoustic grand piano sample set from the
MusyngKite soundfont using `soundfont-player`. The samples are fetched from an
external host when audio is enabled, so internet access is needed unless the
browser has them cached. The first load can take a little while; the page
reports whether MIDI and audio are ready or need to be retried.

Connect a MIDI input and play or release notes to light up the matching keys on
the 88-key A0–C8 piano and hear them through the computer's audio output.
Incoming note velocity controls playback volume. Piano key highlights follow
the note-on/note-off state. A sustain pedal can keep a released note sounding;
disconnecting an input releases its held and sustained notes. MIDI access
requires a supported browser and a secure context; `localhost` and `127.0.0.1`
are suitable for local development.

To send incoming notes to a MIDI instrument, choose an output in the **MIDI
output** selector and enable **Send incoming notes to the selected output**.
This MIDI-thru option is off by default. It forwards note-on, note-off, velocity,
channel, and sustain-pedal messages. Turning it off or changing outputs sends
note-offs, releases sustain, and resets pitch bend on the previous output to
avoid stuck notes.

Click any piano key to cycle its tuning mode: normal, **+50 cents** (blue),
then **−50 cents** (amber), then back to normal. The selected offset is applied
to incoming notes at that pitch, including a note that is already sounding.
When MIDI thru is enabled, the app sends MIDI pitch bend on the note's incoming
channel, setting that channel's pitch-bend range to ±1 semitone as needed. This
uses standard MIDI messages and does not require SysEx permission. The receiving
instrument must support pitch bend.

Pitch bend applies to an entire MIDI channel, not an individual note. If
simultaneous notes on the same channel have different tuning offsets, they share
the latest bend and cannot be tuned independently. Notes arriving on separate
channels can be tuned independently.

Use **Start recording** to capture incoming notes, velocity, sustain-pedal
changes, and the pitch-bend events for the selected per-key tuning. Press
**Stop recording** to close any notes that are still held, then choose
**Download .mid** to save `midi-tuner-recording.mid`. Starting a new recording
replaces the previous take. Notes and pedals already held when recording starts
are included. The exported Standard MIDI File includes pitch-bend range setup
events so that the recorded ±50-cent bends play back as intended; the recording
captures MIDI events, not the computer's piano audio.

A MIDI sustain/damper pedal sends controller **64**. While it is down, released
notes continue sounding until the pedal is lifted. The piano panel shows
whether sustain is active; disconnecting the MIDI input releases its sustained
notes as well.

## Design decisions

- **Browser-based JavaScript app:** Vite serves and builds a small client-side
  app. WebMidi.js handles browser MIDI access, while the Web Audio soundfont
  plays a local preview without requiring a connected instrument.
- **88-key piano UI:** The interface covers the standard A0–C8 range. Incoming
  MIDI lights the matching key; clicking a key cycles its tuning through
  normal, +50 cents, and −50 cents.
- **Pitch tuning uses pitch bend:** The current MIDI 1.0 output and recording
  use channel pitch bend with a ±1-semitone range. This is broadly compatible,
  but pitch bend is channel-wide, so notes sharing a channel cannot have
  independent tuning.
- **MIDI thru is opt-in:** Incoming notes and sustain are sent to the selected
  output only when the user enables MIDI thru. Disabling it or changing outputs
  releases held notes and sustain and resets bend to avoid stuck state.
- **Sustain follows MIDI CC64:** Pedal state is tracked per input and channel;
  overlapping pedal sources on a channel are aggregated so one source cannot
  release another source's pedal.
- **Recording captures MIDI events, not audio:** The app exports a Standard
  MIDI File with notes, sustain, and tuning events. Held notes and pedals are
  included when recording starts, and notes still held at stop are closed in
  the take.
- **MIDI 2.0 per-note tuning is an experimental direction, not implemented:**
  The current browser Web MIDI API and WebMidi.js integration expose MIDI
  messages as MIDI 1.0 byte sequences; they do not provide a UMP/MIDI 2.0
  transport in this app. Therefore the current `.mid` download cannot carry
  MIDI 2.0 per-note pitch messages. A true MIDI 2.0 implementation would need
  a UMP-capable transport and compatible destination software or hardware.
  Until that transport exists, using MPE (separate MIDI 1.0 channels per
  active note) is a possible compatibility-oriented alternative, but it is
  not MIDI 2.0 and requires an MPE-capable destination.

## Build process

The production build is created by Vite. From the project folder, run:

```powershell
npm install
npm run build
```

`npm install` installs the dependencies listed in `package.json` (with exact
resolved versions recorded in `package-lock.json`). The build command runs
`vite build`: it reads `index.html`, follows the JavaScript and CSS imports
from `src/`, bundles and optimizes the app, and writes the deployable static
files to `dist/`. Vite clears and recreates that output folder during a build;
do not make source edits directly in `dist/`.
The soundfont audio files are fetched by the browser at runtime; they are not
included in `dist/`.

To check the production build locally, run:

```powershell
npm run preview
```

Vite prints a local preview URL. This preview serves the built files; for
day-to-day development, use `npm run start` or `.\start-localhost.ps1` instead.
